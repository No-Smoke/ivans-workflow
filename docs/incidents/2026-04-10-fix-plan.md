## Phase 2 — Fix the arming race (RC1)

**Goal:** Even with auto-recovery enabled, eliminate the PROCESSING→IDLE arming-after-handoff race.

### 2.1 Add threading lock around stall-watchdog state

- **File:** `iwo/daemon.py`
- **Change:** add `self._stall_watchdog_lock: threading.Lock = threading.Lock()` in `__init__`. Wrap every read, write, arm, clear, and iteration of `_stall_watchdog` and `_stall_alert_sent` in `with self._stall_watchdog_lock:` blocks. Locations: `_poll_agent_states` arming block, `_poll_agent_states` stall-check loop, `process_handoff` pop, startup/init, any cleanup paths.
- **Why insufficient alone:** lock fixes reorderings but not the logical race — still possible to arm for an already-completed spec.
- **Test:** `tests/test_stall_watchdog.py::test_concurrent_arm_and_clear_no_reorder` (uses `threading.Event` to force the two paths to interleave).
- **Commit:** `fix(stall-recovery): add lock around stall watchdog mutations`

### 2.2 Track last-processed-handoff timestamp per (spec, agent)

- **File:** `iwo/daemon.py`
- **Change:** add `self._last_handoff_at: dict[tuple[str, str], float] = {}` keyed by `(spec_id, source_agent)`. Update in `process_handoff` after successful parse+validate+idempotency check, before routing. Value = `time.time()`.
- **Rationale:** gives the arming logic a way to ask "did this agent write a recent handoff for this spec?"
- **Test:** `tests/test_stall_watchdog.py::test_last_handoff_recorded_after_process`
- **Commit:** `fix(stall-recovery): track last handoff time per spec-agent`

### 2.3 Refuse to arm watchdog if a recent handoff from this agent exists

- **File:** `iwo/daemon.py` `_poll_agent_states` arming block
- **Change:** before arming, check `(spec_id, name)` in `_last_handoff_at`. If the last handoff was within `stall_shutdown_grace_seconds` (new config, default 60s — covers Claude CLI pane-exit latency with margin), skip arming and log at DEBUG.
- **Config:** `iwo/config.py`: `stall_shutdown_grace_seconds: float = 60.0`
- **Test:** `tests/test_stall_watchdog.py::test_arming_skipped_within_grace_window` (simulates handoff-then-IDLE ordering from the real incident).
- **Commit:** `fix(stall-recovery): skip arming during post-handoff shutdown grace`

### 2.4 Re-key `_stall_alert_sent` by (agent, spec, armed_at)

- **File:** `iwo/daemon.py`
- **Change:** replace `_stall_alert_sent: set[str]` with `_stall_alert_sent: set[tuple[str, str, float]]` so a resolved stall on spec-A doesn't suppress a subsequent stall on spec-B.
- **GPT-5.2 finding.** Not a cascade cause but would mask future incidents.
- **Test:** `tests/test_stall_watchdog.py::test_alert_per_spec_not_per_agent`
- **Commit:** `fix(stall-recovery): key alert dedup by agent+spec+armed_at`

### 2.5 Move watchdog-clear to after idempotency check in process_handoff

- **File:** `iwo/daemon.py` `process_handoff` ~line 1128
- **Change:** move `self._stall_watchdog.pop(...)` block to after `self.tracker.already_processed(handoff, path)` passes and before routing.
- **Rationale:** prevents a superseded or rejected handoff from clearing legitimate stall state.
- **Test:** `tests/test_stall_watchdog.py::test_superseded_handoff_does_not_clear_watchdog`
- **Commit:** `fix(stall-recovery): clear watchdog only for accepted handoffs`

## Phase 3 — Fix auto-recovery generation (RC2 + sequence correctness)

**Goal:** When auto-recovery is legitimately needed, it must not corrupt the chain.

### 3.1 Replace file-count-as-sequence with parsed max sequence

- **Files:** `iwo/auto_handoff.py` (generator), `iwo/daemon.py` lines ~338–345 (caller)
- **Change:** new helper `_max_existing_sequence(spec_dir: Path) -> int` that parses the `NNN-` prefix or JSON `metadata.sequence` from all `*.json` files in the dir (excluding `LATEST.json`). Use this instead of `len(existing)`. Return 0 if empty.
- **Rationale:** GPT-5.2 finding. `len()` breaks under quarantine, non-handoff files, or gaps.
- **Test:** `tests/test_auto_handoff.py::test_max_sequence_with_gaps_and_phantoms`
- **Commit:** `fix(auto-handoff): compute max sequence from filenames, not file count`

### 3.2 Add downstream-progress check to generate_auto_handoff

- **File:** `iwo/auto_handoff.py:generate_auto_handoff`
- **Change:** before generating, scan `spec_dir` for any handoff file whose agent is downstream of `agent_name` in `AGENT_ORDER` (or whose sequence > last_sequence). If found, return `None` with `log.warning("Skipping auto-handoff for {agent_name}/{spec_id}: downstream progress detected")`.
- **Test:** `tests/test_auto_handoff.py::test_skipped_when_downstream_handoff_exists`
- **Commit:** `fix(auto-handoff): abort generation when downstream chain has progressed`

### 3.3 Fix stdout/stderr parsing in _run_tests

- **File:** `iwo/auto_handoff.py:_run_cmd` and `_run_tests`
- **Change:** `_run_cmd` returns `(returncode, stdout, stderr)` instead of concatenated output. `_run_tests` parses JSON from stdout only. Fallback path unchanged.
- **Rationale:** GPT-5.2 finding. Current concatenation guarantees `json.loads` fails in most cases, silently using the heuristic fallback and producing misleading pass/fail counts in auto-handoff notes.
- **Test:** `tests/test_auto_handoff.py::test_run_tests_parses_json_with_stderr_noise`
- **Commit:** `fix(auto-handoff): parse vitest JSON from stdout only`

### 3.4 Make test-directory configurable

- **Files:** `iwo/config.py`, `iwo/auto_handoff.py`
- **Change:** add `auto_handoff_test_dir: Optional[str] = None`. If None, use `npm test` or `npx vitest run` without a directory filter. Remove hard-coded `src/__tests__/hybrid-calculator/`.
- **Rationale:** GPT-5.2 finding. Hard-coded path means an auto-handoff for any non-hybrid-calculator spec runs the wrong tests and can claim "tests pass" based on an irrelevant subset.
- **Test:** `tests/test_auto_handoff.py::test_uses_configured_test_dir`
- **Commit:** `fix(auto-handoff): make test directory configurable`

### 3.5 Move auto-handoff generation to background thread

- **File:** `iwo/daemon.py` `_poll_agent_states`
- **Change:** when auto-recovery fires, mark the watchdog entry as "recovery in progress" and spawn a daemon thread for `generate_auto_handoff`. The thread acquires the lock, re-checks predicates (downstream progress may have landed since the poll), generates the handoff, writes atomically, releases.
- **Rationale:** GPT-5.2 finding. Current implementation blocks the 2s poll loop for 30–60+ seconds during test/typecheck runs, which means state polling freezes and more phantom conditions can develop.
- **Test:** `tests/test_stall_watchdog.py::test_recovery_runs_off_poll_thread` (mock slow `_run_tests`, assert poll continues)
- **Commit:** `fix(stall-recovery): run auto-handoff generation in background thread`

## Phase 4 — Fix handoff ingestion safety (RC3 + latent issues)

**Goal:** Even if a phantom handoff is written (by any path), the daemon should refuse to dispatch it onto a live chain.

### 4.1 Enforce monotonic per-spec sequence at ingestion

- **File:** `iwo/daemon.py` HandoffTracker class
- **Change:** add `self._max_seq_per_spec: dict[str, int] = {}`. In `process_handoff`, after parse/validate but before idempotency, check `handoff.sequence > self._max_seq_per_spec.get(handoff.spec_id, 0)`. If not, reject with log.warning and notify. Exception: explicit rejection handoffs (`handoff.is_rejection`) bypass this check.
- **Rationale:** would have prevented the `014-docs` vs `014-tester` collision.
- **Test:** `tests/test_handoff_tracker.py::test_rejects_non_monotonic_sequence`
- **Commit:** `fix(tracker): enforce monotonic sequence per spec`

### 4.2 Gate LATEST.json update on successful validation

- **File:** `iwo/daemon.py` lines 167–179 (HandoffHandler._handle_new_handoff)
- **Change:** remove the symlink update from the watcher callback. Move it to `process_handoff` immediately after successful parse+validate+idempotency+safety-rail checks, before routing.
- **Rationale:** GPT-5.2 finding. Currently a phantom or malformed file momentarily becomes "latest" before being rejected, which interacts badly with the 30s reconciliation loop and Nextcloud rename events.
- **Test:** `tests/test_handoff_handler.py::test_latest_not_updated_for_invalid_handoff`
- **Commit:** `fix(handoff): update LATEST.json only after validation`

### 4.3 Reject stale queue items on startup

- **File:** `iwo/daemon.py` PipelineManager and startup sequence
- **Change:** on daemon startup, walk `pipeline._queues` and drop any enqueued handoff whose file mtime is older than `self._started_at` minus `stale_queue_grace_seconds` (new config, default 300s). Log each dropped item.
- **Rationale:** explains the phantom "EBATT-106 #7" queue drain during the incident. The stale Sprint 1 planner handoff survived a restart and was re-dispatched.
- **Test:** `tests/test_pipeline.py::test_stale_queue_items_dropped_on_startup`
- **Commit:** `fix(pipeline): drop stale queue items on startup`
